# Staff App and Public Pages (Frontend) Implementation Plan

> Execute task by task, in order. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Baroda Lending Desk (Demo) web app: sign-in with one-click demo roles, every staff screen over the existing FastAPI API, and the public D2–D4 pages, hosted on Vercel.

**Architecture:** A static Vite + React single-page app in `frontend/`. Supabase Auth is used only to sign in; every read and write goes to the FastAPI backend with the Supabase access token as `Authorization: Bearer`. Server responses drive what each role may do (the `actions` flags and `/me` permissions); the browser never decides an outcome. The design system is ported from the reference app (`fbivinay/Odoo-Hackathon-Finals-Textile-Manufacturing`, folder `web/`) with the brand colour changed.

**Tech Stack:** Vite, React 19, TypeScript, React Router 7, Tailwind CSS v4, shadcn/ui (Radix), Geist fonts, TanStack Table, Recharts, lucide-react, sonner, `@supabase/supabase-js` (auth only), `mermaid` (lazy, architecture page only). Unit tests with `node --test` (Node 24 strips TypeScript types natively).

**Spec:** `docs/PLAN.md` section 14A (frontend design, approved 26 Nov 2026, Vite instead of Next.js), with sections 2 (scope), 16C–16L (API behaviour per phase) and 17 (deliverables D1–D4).

## Global Constraints

- Desktop and laptop only: layouts target widths of 1280 px and up. No mobile or tablet layouts.
- Brand tokens: `--brand: #C2410C`, `--brand-tint: #FFF7ED`, `--brand-deep: #7C2D12`, `--brand-soft: #FED7AA`. White text on `--brand` and `--brand` text on white must meet 4.5:1 (it is about 5.2:1).
- Wordmark: "Baroda Lending Desk" with a "Demo" tag. No Bank of Baroda logo, no official brand assets.
- Colour appears only as brand or as status: good `#16704a`/`#e6f2ec`, watch `#96600a`/`#f8efdc`, problem `#a82e22`/`#fbe9e7`, neutral `#6b6b74`/`#eeeef0` (the reference's values).
- Status tones (14A): good = APPROVED, SANCTIONED, DISBURSED, RECOMMENDED_FOR_APPROVAL, VERIFIED. watch = DISCREPANCY, FORWARDED, UNDER_REVIEW, RECONSIDERATION, REFER_FOR_FURTHER_REVIEW. problem = DECLINED, POTENTIALLY_INELIGIBLE, REJECTED, FAILED, BOUNCED, COMPLAINED. Everything else neutral (includes DRAFT, INTAKE, DOCS_PENDING, DEMO_ASSUMPTION).
- Every AI recommendation shows the words "AI recommendation, human decides". Extraction method `PREPARED_DEMO_TEXT` always reads "Prepared demo data — not OCR".
- Labels the API returns (`label`, `banner`, `permission_label`, `routing`, `disclaimer`) are shown verbatim, never reworded or hidden.
- No chat assistant. No Bank of Baroda claims: all data is synthetic and every document view carries the API's demo label.
- The browser talks to Supabase for sign-in only, never to tables or storage. Documents open through the API's 60-second signed URLs.
- Environment (`frontend/.env.local`, never committed; `frontend/.env.example` committed with empty values): `VITE_API_URL`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_DEMO_PASSWORD`. The demo password ends up in the public bundle; this was accepted in 14A.
- Dev server on port 3000 (the backend's default `FRONTEND_ORIGIN` is `http://localhost:3000`).
- Path alias `@/` → `frontend/src/`. Files under `src/lib/` that tests import use relative imports with the `.ts` extension (`allowImportingTsExtensions`), so `node --test` can load them.
- Motion: one easing family and the reference's two durations; everything off under `prefers-reduced-motion`. The splash shows for at most 1.2 s, ends on any click or key, and is skipped entirely under reduced motion.
- Indian formats: rupees with lakh/crore grouping (`₹4,00,000`; compact `₹4.5 L`, `₹1.48 Cr`); dates `26 Nov 2026`; times in Asia/Kolkata, `3:07 pm`.
- Commits: only as `git -c user.name=fbivinay -c user.email=rvinaykumar6924@gmail.com commit`, with no `Co-Authored-By` or any other trailer, and no mention of AI tools in code, comments or docs. Commit a task only when `npm run build` and `npm test` (in `frontend/`) both exit 0.
- Screen checks run the local backend (`backend/.venv/Scripts/uvicorn app.main:app --port 8000` from `backend/`) against the live Supabase project. They create real demo records; use customers from `BOB-C0040` upward so they don't collide with the documented demo journey, and list what was created in the task's commit message.

## Review Focus

1. **Render cold start:** the first call after 15 idle minutes can take about a minute. Expected: the sign-in page pings `/health` on load and shows "Waking the server (free tier, up to a minute)…" until it answers; a request that fails at the network level shows the waking message, not a crash. Test: `errorMessage(0)` in Task 2.
2. **Stale version (409):** another person changed the application. Expected: the API's message in a toast with a "Reload" action, the data refetched, and nothing overwritten. Test: `errorMessage(409, …)` in Task 2; screen check in Task 6 (claim the same file in two tabs).
3. **Session expiry:** Supabase tokens last an hour. Expected: `supabase-js` refreshes silently; if the API still answers 401, the user is signed out to `/sign-in` with "Your session has ended. Sign in again." Test: `errorMessage(401)` in Task 2.
4. **Buttons a role cannot use:** expected: hidden, using the API's `actions` flags (review, disbursement) or `/me` permissions; a 403 still shows the API's message. Test: `navFor` per role in Task 2; screen check in Task 6 (Loan Officer sees no Decide buttons).
5. **Wrong file on upload:** expected: the browser refuses anything other than PDF, PNG or JPEG, and anything over 10 MB, before sending, using the same limits as the API; an API 413, 415 or 422 shows its message verbatim. Test: `checkUpload` in Task 5.

**Interfaces:**
- Produces:
  - **Types and errors:**
    - `type Role = 'LOAN_OFFICER' | 'ASSISTANT_MANAGER' | 'BRANCH_MANAGER'`
    - `type Me = { user_id: string; full_name: string; email: string; role: Role; permissions: string[] }`
    - `class ApiError extends Error { status: number }`
    - `errorMessage(status: number, detail?: unknown): string` (pure)
  - **`api<T>(path: string, init?: { method?: string; body?: unknown; file?: File; signal?: AbortSignal }): Promise<T>`**
    - Bearer token from the current Supabase session. JSON body, or the raw `File` with its own `Content-Type`.
    - Throws `ApiError` with `errorMessage(...)`.
    - On 401 it calls `supabase.auth.signOut()`.
    - Timeout 90 s.
  - **`useApi<T>(path: string | null, opts?: { pollMs?: number; until?: (d: T) => boolean })`**
    - Returns `{ data?: T; error?: ApiError; loading: boolean; reload: () => void }`.
    - Polls every `pollMs` while `until` returns false.
    - A `null` path fetches nothing.
  - **`useAction()`**
    - Returns `run<T>(fn: () => Promise<T>, opts?: { ok?: string; onDone?: () => void }): Promise<T | undefined>`.
    - Toasts success, or the error message.
    - On 409 the toast has a "Reload" action that calls `onDone`.
  - **`SessionProvider`, and `useSession()`**
    - `useSession()` returns `{ me: Me | null; loading: boolean; signIn(email: string, password: string): Promise<void>; signOut(): Promise<void> }`.
    - `me` comes from `GET /me` after sign-in and on reload.
  - **`can(me: Me | null, ...perms: string[]): boolean`** (true if any of `perms` is held)
  - **Navigation:**
    - `type NavItem = { to: string; label: string; icon: LucideIcon; any: string[] }`
    - `NAV: NavItem[]`
    - `navFor(perms: string[]): NavItem[]`
